# ADR 2026-07-24

See #57.

`CentralisedSimulation.setup()` hardcodes an IID split (shuffle + equal-size
shard) with no seam to inject a different partitioning strategy.
`DecentralisedSimulation` takes an already-built list of per-worker data
streams and never touches partitioning itself — the caller owns it entirely,
IID or not.

## Decision

Align `CentralisedSimulation` on `DecentralisedSimulation`'s data contract:

- `setup()` stops building shards internally (no more `randperm` + slice
  over a single `train_set`).
- The constructor takes a list of per-worker dataloaders instead of a
  single `train_set`, mirroring `DecentralisedSimulation`'s
  `data: Sequence[Iterable[Batch]]`.
- Partitioning becomes entirely the caller's responsibility, for both
  simulation types, before construction.

## Partitioning functions

Ship three plain functions, not a class hierarchy — partitioning is a
one-shot, stateless `dataset + n -> shards` call, unlike the per-round
`Aggregator`/`Attack` primitives which carry state across steps:

- `iid_partition(dataset, n, seed)` — shuffle, split into `n` equal
  shards. Current default behavior.
- `shard_partition(dataset, n, shards_per_worker, seed)` — sort by class
  label, cut into equal shards, deal `shards_per_worker` shards per
  worker at random. Pathological non-IID (McMahan et al.).
- `dirichlet_partition(dataset, n, alpha, seed)` — per class, draw a
  `Dirichlet(alpha)` proportion vector over workers. Continuous skew
  from near-IID (`alpha` large) to extreme imbalance (`alpha` small).

These live outside both simulation classes, as reusable utilities called
before constructing a simulation. A user can always write their own
partitioning function of the same shape instead of using one of the three.

## Scope

- `shard_partition` and `dirichlet_partition` assume classification-style
  discrete labels. Non-classification use (regression, unsupervised)
  requires the caller to derive their own discrete key (quantile-bucketed
  target, cluster id, or an existing grouping attribute) and write a
  matching custom function — not handled by the three built-ins.
- We do not implement feature-distribution skew, concept shift, or
  quantity skew as separate controls. Left to user-supplied partitioning
  functions if needed.
